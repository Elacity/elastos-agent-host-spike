# Live-grant stand-in

This value is the lab stand-in for the shell view of every session's live grants. The real route can replace it later because the JSON matches (M1-R).

`StandIn::get_capability_list` answers `GET /api/capability/list`. `scope: None` is the plain route. `scope: Some("all_sessions_live")` is `GET /api/capability/list?scope=all_sessions_live`. The caller is `Shell` or `Client { session_id }`, a method argument for the authenticated session. It is not a JSON field.

A shell caller receives one body on both forms. The body's keys are `scope` and `capabilities`. `scope` is `all_sessions_live`. Each entry's keys are `request_id`, `session_id`, `resource`, `action`, `duration` and `granted_at`. Entries are sorted by `session_id`, then `request_id`.

A client caller with the plain route receives a body whose only key is `capabilities`. Entries are that session only, sorted by `request_id`. Each entry's keys are `request_id`, `resource`, `action`, `duration` and `granted_at`. A client session with no grant receives `capabilities: []`.

`seed_grant` is a lab test seam, not a route. It stores `request_id`, `session_id`, `resource`, `action`, `duration`, the seeded `granted_at`, a life, and `session_ended`. The four lives are `Live`, `Exhausted`, `Revoked` and `Expired`. One filter keeps a grant whose life is `Live`. `session_ended` leaves that grant in the view.

A scope other than `all_sessions_live` is status 400. The reason starts with `unknown capability list scope:` and contains that scope text. A client that asks for `all_sessions_live` is status 403 with the reason `This endpoint requires shell privileges`.

`run_leaves_no_live_grant` stays blocked on the real Runtime (`AC-021-GRANTS`). A passing `standin_` row gives the Runtime no credit.

`StandIn::post_capsules` answers `POST /api/capsules`. `StandIn::get_capsules` answers `GET /api/capsules`. A shell caller receives status 200. A client receives status 403 and the reason `This endpoint requires shell privileges`.

The launch body's only key is `path`. The launch value's keys are `id`, `name`, `status` and `session_id`. `session_id` equals `id`. The list body's only key is `capsules`. Each entry's keys are `id`, `name`, `status`, `session_id` and `cause`. Entries are sorted by `id`.

The status strings are `starting`, `running`, `stopping`, `stopped` and `failed`. This stand-in stores `starting`, `running`, `stopped` and `failed`. `cause` is empty while `starting` or `running`. A `failed` entry stays while the test-supplied instant is less than 60 seconds after it failed, and the list omits it at 60 seconds. A `starting` or `running` entry stays at every instant.

`admit_resident` stores one path with its name, its `Start`, and the world name `resident-capsule`. `admit_resident`, `finish_start` and `set_instant` are lab test seams, not routes. `finish_start` is the one call to `resident.start`. Launch answers `starting` before that call returns.

`StandIn::delete_capsule` answers `DELETE /api/capsules/:id`. The body's only key is `reason`. The Ok value is null. `cause` is `stopped: ` joined with that reason. A `stopped` entry stays while the test-supplied instant is less than 60 seconds after the stop, and the list omits it at 60 seconds. Each `Live` grant whose session is that instance becomes `Revoked` and drops out through the one life filter. The sibling instance stays.

`StandIn::get_capability_requests` answers `GET /api/capability/requests?session=`. `session` is the query, a method argument, not a JSON field. A shell caller receives status 200 and a body whose only key is `requests`. Entries are that session only, sorted by `request_id`, with keys `request_id`, `session_id`, `resource`, `action`, `reason`, `status`, `decision_reason` and `settled_by`. A pending entry reads `status` `pending`, `decision_reason` `""` and `settled_by` null. An unknown session reads `{"requests":[]}`. A client caller is status 403 with the reason `This endpoint requires shell privileges`, including when the session is missing. A shell with no session, or an empty one, is status 400 with the reason `requests need a session`.

`seed_request` is a lab test seam, not a route. It stores one pending request and refuses an empty id, session, resource or action, and a repeated `request_id`. The reason may be empty. A stop that the shell accepts denies that session's pending requests through the one settlement function: `status` becomes `denied`, `settled_by` becomes `runtime`, and `decision_reason` becomes the same stop cause. A failed start denies that session's pending requests through the same settlement function, and `decision_reason` is the failure cause. A stop still uses the stop cause, and an `Ok` start does not settle. The request is stored while the instance is `starting`. A record of another session stays pending. The real capability call still returns the grant, so this row gives the Runtime no A11 credit. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). The real A10 row stays blocked.

`standin_stopped_run_leaves_no_live_grant` stops both instances of one run. After both stops the shell live view has no grant, and a `stopped` entry is not a live instance: `starting`, `running` and `stopping` are live. `standin_a12_census` calls `get_capability_requests` for each listed session. A `pending` status returns `pending request leftover`; a `denied` status does not. This value is the lab stand-in and the real route can replace it later because the refusal matches (M1-R). `run_leaves_no_live_grant` stays blocked on the real Runtime.

`authorise` is a lab test seam, not a route. A sibling is refused with `wrong capsule`. A successful `authorise` by the owning client of a `once` grant stores `Exhausted`, and the live view omits it through the one life filter. A `session` grant stays `Live` after any number of successful calls. A `once` grant at or past its `expires_at` in the test instant is refused with `grant is not live: Expired` through the same expiry compare the list filter uses. A refusal spends nothing. A stop removes that session's live grant through the one filter. This value is the lab stand-in and the real route can replace it later because the refusal matches (M1-R). `instance_grant_does_not_authorise_sibling` stays the process-isolation row.

It refuses `/tmp/elastos/storage` with status 400 and the reason `shared temp directory is not agent storage`, before the data-directory rule runs, and it creates nothing there. `standin_storage_follows_the_selected_home` and `standin_shared_temp_storage_is_refused` prove that pair. A regular file under the storage directory whose link count is above 1 is refused with the reason `storage file has more than one link`, and it is not read. Any other file type is refused with the reason `storage file is not a single regular file`. `standin_storage_refuses_root_symlink_swap` and `standin_storage_refuses_host_hardlink` prove that pair. `StandIn::post_capability_deny` answers `POST /api/capability/deny`. The body's only keys are `request_id` and an optional string `reason`; a missing reason is `Denied by user`, and the Ok value's only key is `success` with true. A client is status 403 with the reason `This endpoint requires shell privileges`, checked before the body is read. A missing `request_id`, or a body that is not an object, is status 400 with the reason `deny body needs request_id`. A non-string `request_id` or `reason` is status 400 with the reason `deny request_id must be a string` or `deny reason must be a string`. An extra body key is status 400 with a reason that starts `deny body rejects `. An unknown or non-pending `request_id` is status 400 with a reason that starts `unknown request:` or `request is not pending:`. Each refusal changes no record and no instance. The one writer stores `status` `denied`, `decision_reason` equal to the reason and `settled_by` `shell` for that request, and every other record stays. When that session's instance is `Starting`, the same call stores `failed`, the deny reason as its cause, and `ended_at` from the test instant; a `running`, `stopped` or `failed` instance keeps its phase and its cause. `authorise` stays the presentation check. A stop still uses `settled_by` `runtime` through `settle_pending`. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). A PASS gives the Runtime no A6 credit for this deny.

`StandIn::post_capability_grant` answers `POST /api/capability/grant`. The body's only keys are `request_id`, `duration` and `rationale`; a missing `duration` is `session`, and a missing `rationale` is `Shell auto-grant`. A present duration whose lowercase form is `once` or `session` is stored as that lowercase word, and any other duration is status 400 with the reason `Invalid duration: ` plus the given text plus `. Expected 'once' or 'session'`. A present rationale string, including an empty one, is stored as given. The Ok value's only key is `success` with true, and the body has no token. A client is status 403 with the reason `This endpoint requires shell privileges`, checked before the body is read. A missing `request_id`, or a body that is not an object, is status 400 with the reason `grant body needs request_id`; a non-string `request_id`, `duration` or `rationale` is status 400 with the reason `grant request_id must be a string`, `grant duration must be a string` or `grant rationale must be a string`. An extra body key is status 400 with a reason that starts `grant body rejects `. An unknown `request_id` is status 400 with a reason that starts `unknown request:`, and a record whose status is not `pending` is status 400 with a reason that starts `request is not pending:`. Each refusal changes no record, no grant and no instance. The one writer sets that record's `status` `granted`, `decision_reason` to the rationale and `settled_by` `shell`, and every other record stays. `seed_grant` then stores the one `Live` grant the RA-1 view shows: the same `request_id` and `session_id`, the record's `resource` and `action`, the canonical duration, `granted_at` from the test instant, and `session_ended` false. No instance changes phase. A later grant of that id is status 400 with a reason that starts `request is not pending:` and adds no grant. A `once` grant stores its expiry as its `granted_at` plus 3600 seconds in the view's `expires_at`; at or past that instant the one filter drops it from both list forms and `authorise` answers `grant is not live: Expired`. A `session` grant stores no expiry and stays in that view until a stop revokes it. `authorise` stays the presentation check. A deny still uses `settled_by` `shell` with `status` `denied`. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). A PASS gives the Runtime no A6 credit for this grant.

`StandIn::watch_ended` is a lab observation, not a route. It calls `get_capsules` and `get_capability_requests` for one session at the test instant; it reads no clock and no disk. Two seconds after a stop, the instance is still listed `stopped` with one request that is not pending. Two seconds after a failed start, the same holds for `failed`. A pending request on that session is `made a request after it ended`. At 60 seconds the instance has left the list. `seed_request` can still store a pending record after the end, and the watch reports it and does not remove it. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). A PASS gives the Runtime no A10 or A11 credit for this watch.

After one instance has ended, `post_capability_grant` of the survivor's pending request stores one `Live` grant for the survivor's session, and `finish_start` then stores `running`. The ended request stays `denied` with `settled_by` `runtime`. Stopping the survivor makes `standin_a12_census` return success. The grant does not change phase. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). A PASS gives the Runtime no A10 or A11 credit for the survivor.

`set_instant` calls `expire_due`, and a pending request ages from the instant `seed_request` stored in `requested_at`. At 300 seconds the one writer sets `status` `expired`, `decision_reason` `Request timed out` and `settled_by` `runtime`. A granted or denied record stays, and the instance stays. An expired request is not pending, so deny and grant refuse it. This value is the lab stand-in and the real timeout can replace it later because the status matches (M1-R). A PASS gives the Runtime no A10 or A11 credit for expiry.

`StandIn::post_capability_request` answers `POST /api/capability/request`. It calls `seed_request` only for a `starting` or `running` instance, and a `stopped` or `failed` instance is `instance is not live` and stores nothing. The Ok body is `status` `pending` and `request_id`, with no token. `seed_request` can still store a record after the end. This value is the lab stand-in and the real route can replace it later because the JSON matches (M1-R). A PASS gives the Runtime no A10 credit for this refusal.

`StandIn::get_capability_request` answers `GET /api/capability/request/:id`. The id is the path segment, a method argument, not a JSON field, and it reads the one request store. The owning client receives `pending` or `granted` as a body whose only key is `status`. A denied or expired record also carries `reason`, the record's decision reason. A shell, or a client of another session, is status 403 with the reason `Cannot access another session's request`; a missing record is status 404 with `Request not found: ` plus that id. The body carries no token, and the read stores nothing. A PASS gives the Runtime no A11 credit for this later call.
