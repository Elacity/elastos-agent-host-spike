C9 linux-confine on aarch64 guest kernel 6.18 under qemu-system TCG (emulated CPU)

Never native aarch64. Never Jetson.

## How this was run

  lab/linux-confine/run-aarch64-guest.sh full

Host: Linux 6.12.94+ x86_64
qemu-system-aarch64 8.2.2, -accel tcg, -cpu max, -M virt
Cross compiler: aarch64-linux-gnu-gcc 13.3.0
rustc 1.91.0, target aarch64-unknown-linux-gnu
Guest kernel: Alpine virt 6.18.58-0-virt (linux-virt-6.18.58-r0.apk)
Guest userspace: Alpine 3.23.5 minirootfs plus the Ubuntu aarch64 glibc loader
Guest uid: 1000 (tester). Root would have CAP_MKNOD and would change the
make-char / make-block controls.

Landlock ABI inside the guest: 7 (ioctl_dev_ready=yes).
Syscall numbers come from aarch64 <sys/syscall.h> (landlock_* = 444/445/446).

## What differs from the x86_64 host run

The C9 permitted/denied results match. These fields differ, as expected:

1. enforced abi=7 on Linux 6.18.58-0-virt. The x86_64 host (Linux 6.12.94+)
   reports abi=6. Both are >= 5, so IOCTL_DEV is expressed on both.
2. Dynamic linker and libraries are aarch64 glibc paths
   (/lib/ld-linux-aarch64.so.1, /lib/aarch64-linux-gnu/libc.so.6,
   libgcc_s.so.1, and libm.so.6 on wallet and model). x86_64 uses
   /lib64/ld-linux-x86-64.so.2 and /lib/x86_64-linux-gnu/*.
3. Seccomp AUDIT_ARCH_AARCH64 and aarch64 SYS_* numbers. Tests assert errno
   and reasons, not the numbers.
4. First guest run lost the model unbound-exec errno=13 line: the launcher
   prints `enforced` before execve, and TCG scheduled the test to read
   stderr before the EACCES line. providers.rs now waits up to 5s for
   errno=13. That is a harness wait, not a weaker filter. Re-run: 4/4.

## What remains for real ARM hardware

This is an emulated CPU (qemu-system TCG) with a real aarch64 kernel.
It is not a Jetson and not any other aarch64 board. A production claim
for ARM still needs the same suites on that board, kernel >= 6.7 so
Landlock ABI >= 5 can express IOCTL_DEV, with the shipping binaries
linked the way that board ships them.
