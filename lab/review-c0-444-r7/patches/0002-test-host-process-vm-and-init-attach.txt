Host process_vm_readv cannot be closed by dumpable 0 or by init as
the exclusive tracer. A 1:1 unprivileged userns sets ns->owner to the
caller's euid, so every same-uid host process has CAP_SYS_PTRACE in
that namespace (kernel cap_capable owner walk). PTRACE_ATTACH is
busy only because one tracer is allowed. process_vm_readv and
pidfd_getfd do not need to be the tracer.

Directions that would close the host path, none of them are this lab
on an unprivileged 1:1 map:

- host Yama ptrace_scope>=1 (host policy, not the guard)
- a privileged map whose owner kuid is not the host euid
- parent traces init (closes init attach only, not process_vm)
